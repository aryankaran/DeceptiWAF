Naïve WAFs run pattern matching against the raw request body — and attackers know this. They encode payloads to slip past regex. HTML entities like <script> look harmless to a rule looking for the literal <script> tag, so the attack reaches the page. Full-width Unicode characters like ＭＭＲＭ slip past SQL pattern rules. SQL comments like UNION slash-star star-slash SELECT break the contiguous pattern. Double URL-encoding like %2527 hides the apostrophe from a single decode pass. And whitespace padding breaks the literal UNION-SELECT match. Each of these defeats a single-pass WAF. DeceptiWAF’s pipeline runs five normalization layers — decodeURIComponent recursively, decode HTML entities, NFKC Unicode normalize, strip SQL comments, collapse whitespace — before matching. So no matter how the attacker encodes their payload, by the time we run our 50+ regex rules, the payload is in its canonical form and the rule fires.
