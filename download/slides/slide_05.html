50+ rules · 4 attack families · 8 evasion techniques defeated

The WAF engine is built around two ideas: scoring and de-obfuscation. First, scoring. Every regex rule carries a point value, and a request's score is just the sum of every rule it triggers. The block threshold is four. This is deliberately forgiving — a single low-score indicator like a double dash in a legitimate comment won't trip the WAF, because real attacks almost always fire multiple high-score rules simultaneously. The table on the left shows this in action: plain UNION SELECT scores four and gets flagged, but adding a SQL comment pushes it to five and triggers a hard block. Second, de-obfuscation. Before any pattern matching runs, the input flows through a five-stage pipeline: triple URL decoding, HTML entity decoding, Unicode NFKC normalization, SQL comment stripping, and only then the fifty-plus rule pattern matcher. Together, these stages defeat eight known evasion techniques — double-encoded payloads, full-width Unicode, inline comments, and more.
