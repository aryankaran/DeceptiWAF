SLIDE 2: Modern Web Security Threat Landscape

Background analysis & motivation behind DeceptiWAF

Current Attack Trends

  • 65%+ Web Breaches originate from SQL Injection (SQLi) and credential stuffing botnets.
  • Automated Tooling (sqlmap, nikto, hydra) systematically scans web endpoints 24/7.
  • Resource Exhaustion: Brute-force floods exhaust server CPU cycles and database connection pools.

Evasion Complexity

  • Multi-Level Encoding: Attackers wrap payloads in percent-encoding (`%2527`) to bypass basic filters.
  • Inline Comment Tricks: Inserting `UNION/**/SELECT` breaks naive regex substring checks.
  • HTML Entity Obfuscation: Using `<script>` evades basic string matchers.
Key Architectural Rationale: DeceptiWAF was designed specifically to address both brute-force credential stuffing and obfuscated SQLi/XSS payloads that bypass legacy WAFs.

SLIDE 3: Problem Statement — The Flaws of Passive WAFs

Why traditional HTTP 403 Forbidden responses fail in production

1. Immediate Attacker Feedback

A 403 status explicitly informs the attacker that their payload was detected. They instantly adjust signatures until the block is bypassed.

2. Zero Attacker Friction

Standard WAFs incur zero time cost on the attacker. Botnets continue probing endpoints endlessly without penalty.

3. False Positive Friction

Overly aggressive WAF regex rules block legitimate users, destroying user experience and generating support tickets.

Research Paradigm Shift: Move from Passive Rejection (HTTP 403) to Active Deception — silently trapping attackers inside isolated decoy portals.

SLIDE 7: AST-Based WAF Engine & Tokenizer

File: `lib/astWaf.js` — Structural token analysis over raw string matching

AST Token Types

  • KEYWORD: SELECT, UNION, DROP, DELETE, WHERE
  • OPERATOR: =, !=, <>, ;, +, -, *
  • STRING / NUMBER: Quoted literals and numeric values
  • COMMENT: Inline `/*...*/` and line `--` comments

AST Structures Analyzed

  • Tautology Detection: `LITERAL OPERATOR LITERAL` (e.g. `1=1` or `'a'='a'`).
  • UNION SELECT Sequence: Checks keyword sequence ignoring comment filler.
  • Stacked Query Check: Detects `;` followed by sensitive SQL keywords.
Why We Chose AST over Regex/ML: AST tokenization eliminates white-space & comment obfuscation vulnerabilities while running in sub-millisecond (<1.5ms) CPU time without heavy ML GPU requirements.

SLIDE 8: De-obfuscation Pipeline & Edge Cases

File: `lib/waf.js` — Multi-layer normalization before inspection

1. Recursive URL Decoding

Decodes up to 3 depth layers of percent-encoding to reverse double-encoding evasion (`%2527` → `%27` → `'`).

2. HTML Entity Mapping

Converts named (`&lt;`), decimal (`&#60;`), and hex (`&#x3c;`) entities back to raw HTML characters before XSS checks.

3. Comment Stripping

Strips inline SQL block comments (`/*...*/`) to normalize fragmented keywords (`UNI/*foo*/ON`).

Why We Chose Normalization: Normalizing raw payloads to canonical representation *before* rule matching guarantees that obfuscation variations resolve to the exact same AST structure.

SLIDE 9: Sliding-Window Rate Limiting Core

File: `lib/ratelimit.js` — IP request tracker with burst defense

Algorithm: Sliding Window

Maintains an in-memory Map of millisecond request timestamps per IP address. Prunes timestamps older than the cutoff window (`WINDOW_MS = 60000`).

Why Sliding Window over Fixed Window?

Fixed windows suffer from "boundary burst exploits" (59 reqs at 0:59 + 60 reqs at 1:01 = 119 reqs in 2 sec). Sliding windows evaluate exact millisecond intervals, eliminating boundary exploits.

Response Action: Triggers HTTP 429 (`Too Many Requests`) with `Retry-After` header and broadcasts `ratelimit_event` via WebSockets.

SLIDE 11: Deterministic Decoy Profile Generation

File: `lib/fakeProfile.js` — IP SHA-256 hash seeding

Deterministic Seeding Formula

hash = crypto.createHash('sha256').update(ip).digest('hex')

Uses numeric integer offsets from the SHA-256 hash to deterministically select Student Name, Roll No., CGPA, Enrolled Courses, and Attendance records.

Why Determinism is Essential

If fake identities changed randomly on every page refresh, the attacker would immediately suspect a honeypot. Determinism ensures 100% session persistence and complete attacker isolation.

Outcome: Side-by-side visual inspection confirms real (`dashboard.html`) and decoy (`honeypot.html`) academic pages look identical in layout.

SLIDE 13: SQLite Persistence Layer & Schema

TABLE events: (id PK, seq, kind, type, attack_type, score, ip, method, path, hits_json, timestamp, server_time, geo_json)

Why We Chose SQLite WAL Mode: SQLite runs zero-latency in-process C queries with zero network socket overhead. WAL (Write-Ahead Logging) mode enables concurrent non-blocking reads during log writes (<0.5ms per query).
